## The 20 "not verified" marks on numbers

All 20 are false alarms: no mark points at a number that is actually unsupported, while some wrong answers
(dated-04, dated-06's "20 August") carry no "not verified" mark on their key date.

| Kind | Marks | Where |
|---|---|---|
| Correct value, in a source the answer did not quote or cite (tranche $6,092) | 2 | why-02, example-2 |
| Date written out whose dd.mm is in a source the answer did not cite ("1 Sep", "7 Sep", "30 Aug") | 3 | why-02 two, dated-09 |
| ISO date split into parts ("2026-08-29" gives 08 and 29) | 4 | id-03 |
| Time split into parts ("04:53", "08:45") | 2 | dated-04, example-3 |
| List numbering "(1)", "(2)" | 2 | id-04 |
| Single digit in the text ("exit 0", "8GB", "±5%", "7 days") | 4 | dated-06 two, id-01, dated-10 |
| Rounding to one significant digit ("+0.6" from "+0.62") | 2 | dated-05 |
| Fee tier written as a decimal ("0.05" for "005") | 1 | dated-10 |

Per answer: why-02 3, dated-04 1, dated-05 2, dated-06 2, dated-09 1, dated-10 2, id-01 1, id-03 4, id-04 2,
example-2 1, example-3 1; every other answer has none.

**Proposed rule changes** (for the owner's decision, not built): read ISO dates and hh:mm times as one token and
check them like dd.mm dates; do not mark list numbering; leave single-digit numbers unmarked rather than "not
verified"; allow rounding to one significant digit when the source has the same leading digit. A date or figure that
appears in a source the answer did not cite stays "not verified": the mark is about what the answer's own quotes back.
